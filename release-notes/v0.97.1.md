## Changed

- **`callum-dev update` cleans up the last no-mistakes config** - Every update now deletes a leftover `.no-mistakes.yaml` and removes the seven `Bash(no-mistakes ...)` allow entries from `.claude/settings.json`, whatever the stamp or baseline says. Other allow entries are untouched. A leftover `.no-mistakes/` folder is only reported, never deleted. The consumer templates (gitignore, devcontainer, README) no longer mention no-mistakes. ([#1329](https://github.com/cbundy/dev-system/pull/1329))
- **The merge train runs for dev-system itself** - This repo's factory loop now merges through the merge train (`mergeTrain` in `.claude/factory-loop.json`), falling back to the plain merge queue when the tested tree or state does not match. Nothing changes for consumer repos. ([#1328](https://github.com/cbundy/dev-system/pull/1328))

## Upgrade

- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`. Expect `removed` lines for `.no-mistakes.yaml` and the no-mistakes allow entries; commit the result. Delete a reported `.no-mistakes/` folder by hand if you no longer need it.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).

## Verify

- In a consumer with `.no-mistakes.yaml` and the `Bash(no-mistakes ...)` allow entries, run `npx callum-dev update` and confirm both are removed and other allow entries survive.
- Run `npx callum-dev update` a second time and confirm it reports `Already in sync`.
- With a `.no-mistakes/` folder present, confirm update prints a `leftover` line and leaves the folder in place.
- Run `npx callum-dev init` in an empty folder and confirm no file mentions no-mistakes.
- Confirm `.claude/factory-loop.json` on the tag has `"mergeTrain": true`, and after the loop picks up the tag, that a merge records `train=rode` with `tree_matched` true.
