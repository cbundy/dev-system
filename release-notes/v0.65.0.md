## New

- **Flaky tests get one bug each** - When the same test flakes at least twice in a week, the loop files one `flaky` bug for it with the evidence, links it under the flake epic (new `flakeEpic` setting) and comments on it for each later flake. It marks the bug `ready` only while fewer than two flake bugs are ready or in flight. New settings: `flakeWindowDays`, `flakeBugMin`, `flakeBugReadyCap` (migration 0016). ([#1092](https://github.com/cbundy/dev-system/pull/1092))
- **Flakes are recorded where they happen** - A stop gate pass that follows a fail on the same clean head is marked flaky on its `gate_run` event, with the tests that failed. Each CI re-run now records whether it was a flake, with the failed jobs and tests. ([#1083](https://github.com/cbundy/dev-system/pull/1083), [#1082](https://github.com/cbundy/dev-system/pull/1082))
- **Already-done issues are closed, not redesigned** - When the designer finds an issue's work already merged on the default branch, the loop checks the evidence, closes the issue with a comment naming the PR or commit, and tells the owner. ([#1087](https://github.com/cbundy/dev-system/pull/1087))
- **Setting changes are logged** - The loop writes one `settings_changed` event for each setting that changed between passes, with the old and new value and who changed it. ([#1094](https://github.com/cbundy/dev-system/pull/1094))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.53.0. A loop workspace with the migrator secret applies migration 0016 itself at start-up.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
