## Breaking

- **no-mistakes is removed from the base image** - The image no longer installs, configures or starts no-mistakes: the binary, the `NM_HOME` / `NO_MISTAKES_*` variables, the `/persist/no-mistakes` folder, the model config and the recovery scripts are gone, and `dev-init` skips its no-mistakes steps. `dev-version` and the HUD versions line no longer list it. Anything that still calls `no-mistakes` must stop. The deprecated `callum-tools` feature drops `installNoMistakes` and `codexModel` and moves to 2.0.0. ([#1325](https://github.com/cbundy/dev-system/pull/1325))
- **The no-mistakes copy jobs are gone** - `nm-export` and `nm-push-loop` no longer exist or run, `dev-doctor` and the heartbeat stop checking them, and the heartbeat's push status has no `nm` key. The existing no-mistakes tables in the shared database are kept, untouched. ([#1324](https://github.com/cbundy/dev-system/pull/1324))
- **Reports no longer read no-mistakes data** - `callum-flow-evaluate` drops its `pipeline` section and pipeline spend rows; `--nm-state` and `--nm-export` are still accepted but ignored, with a note in `sources`. Lead time starts at the loop's review step. The heartbeat busy check and the loop's stale-claim check use only factory events and PRs. ([#1322](https://github.com/cbundy/dev-system/pull/1322))

## Changed

- **Dev container template drops the no-mistakes volume** - The base-image devcontainer template, and this repo's own dev container, no longer mount a no-mistakes storage volume. ([#1325](https://github.com/cbundy/dev-system/pull/1325), [#1326](https://github.com/cbundy/dev-system/pull/1326))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update` (removes the no-mistakes volume line from `.devcontainer/devcontainer.json`).
- Base image: rebuild or re-pull the dev container to get image 2.76.0. Update the plugin at the same time, or an older plugin may say once that the container looks out of date. The old no-mistakes Docker volume is no longer used and can be deleted.
- Scripts or dashboards that read `pipeline` from `callum-flow-evaluate`, the heartbeat's `nm` key or the `no-mistakes` binary must move off them.

## Verify

- On the new image, confirm `no-mistakes`, `nm-export` and `nm-push-loop` are not on PATH, no `NM_HOME` or `NO_MISTAKES_*` variable is set and `/persist/no-mistakes` is not created.
- Confirm `dev-init` completes and `dev-doctor` reports no no-mistakes lines.
- Run `dev-version` and confirm no no-mistakes component; confirm the HUD versions line has no `nm`.
- Run `callum-flow-evaluate --nm-export /nonexistent` and confirm it exits 0 with no `pipeline` key and one retired note in `sources`.
- Confirm the heartbeat push status shows no `nm` key and no `nm_push_not_running` code.
- After `npx callum-dev update` in a consumer, confirm the devcontainer has no no-mistakes volume.
