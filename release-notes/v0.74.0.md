## New

- **Issues held are capped by memory** - The loop now limits how many issues it holds at once by the container's memory as well as `maxInFlightIssues`. Two new settings, `slotMemoryMiB` (`auto` learns the memory a gate run adds, otherwise 3072 MiB) and `memoryReserveMiB` (default 2048), set the ceiling; `/factory config` shows it and the loop says once when memory is the lower bound. ([#1158](https://github.com/cbundy/dev-system/pull/1158))

## Changed

- **Agent gate runs share the stop gate's slots** - With `gateConcurrency` set, an agent's own `npm test` or `npm run lint` now waits for the same container-wide gate slots as the stop gate, so full gate runs no longer pile up past the limit. A stop gate that waits too long for a slot ends as gate-unknown and names the wait. ([#1157](https://github.com/cbundy/dev-system/pull/1157))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

## Verify

- Confirm `/factory config` shows the Capacity rows: `slotMemoryMiB`, `memoryReserveMiB`, the container memory and the effective cap.
- On a loop with `gateConcurrency`, confirm an agent's `npm test` writes an `agent-gate` line to the companion log and waits while the stop gate holds every slot.
- Confirm a stop gate that waited for a slot records `slotWaitMs` in factory-gate.json.
- Confirm the pass log's `cap` field carries effective, configured and ceiling values.
