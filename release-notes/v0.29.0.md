## Changed

- **One watcher for the orchestrator** - The issue orchestrator arms a single `orchestrator-watch.sh` instead of separate queue and pipeline watchers plus an hourly cron audit. It streams while work is in flight and waits single-shot while idle, so an idle orchestrator wakes far less often ([#453](https://github.com/cbundy/dev-system/pull/453))

## Fixed

- **Watchers survive a killed sleep** - The queue, pipeline and orchestrator watchers keep polling when something kills their sleep between polls, instead of exiting and silently stalling the orchestrator ([#451](https://github.com/cbundy/dev-system/pull/451))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`.
- Base image: rebuild or re-pull the dev container for the watcher fix.

## Verify

- An idle orchestrator session runs one single-shot `orchestrator-watch.sh` and no hourly cron
- Adding a `ready` label wakes an idle orchestrator, and a pipeline event reaches an active one
- Killing a watcher's `sleep` child leaves the watcher running with one stderr line
