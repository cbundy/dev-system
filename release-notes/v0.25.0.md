## New
- **Version as data** - `dev-version --json` and `--local` report the running and latest versions as JSON or without a network check, and `dev-init` writes a version snapshot on every start ([#357](https://github.com/cbundy/dev-system/pull/357)).
- **Workspace identity** - Coder workspaces now carry their role, rollout ring, name and template version as `DEV_ROLE`, `DEV_RING`, `DEV_CODER_WORKSPACE` and `DEV_CODER_TEMPLATE_VERSION` ([#348](https://github.com/cbundy/dev-system/pull/348)).
- **Closed issues tracked** - `callum-flow-sweep` records issues closed outside the factory (by hand, as abandoned or by merge) as a `closed` event, so metrics no longer count them as still open ([#361](https://github.com/cbundy/dev-system/pull/361)).

## Changed
- **Durable, unique events** - desktop containers keep `/persist/events` across rebuilds and every factory event gets a unique `event_id`, so events are never lost or double counted ([#353](https://github.com/cbundy/dev-system/pull/353)).
- **Complete pipeline metrics** - pipeline latency and cost now come from the no-mistakes run mirror linked by branch name, so runs no longer drop out when an agent forgets `run_started`; a new query lists runs it cannot link ([#351](https://github.com/cbundy/dev-system/pull/351)).

## Fixed
- **No replayed watcher events** - the queue and pipeline watchers no longer log old states again after a restart ([#360](https://github.com/cbundy/dev-system/pull/360)).

## Upgrade
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update` (desktop consumers get the `/persist/events` volume from it).
- Base image 2.24.0: rebuild or re-pull the dev container (Coder: update the workspace).
