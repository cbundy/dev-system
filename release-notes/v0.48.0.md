## New

- **Factory events are written twice and shipped to the new database** - Every `callum-flow-event` call now also writes the event in the new format beside today's line, and a new background loop, `factory-event-push-loop`, ships those events to `factory.event_store` using the writer role only. It starts with the workspace once the writer secret is set, and `dev-doctor` reports when it is not running. Today's event log and push are unchanged. ([#746](https://github.com/cbundy/dev-system/pull/746), [#756](https://github.com/cbundy/dev-system/pull/756))

## Fixed

- **Merged issues no longer keep their claim** - The heartbeat, the claim command and the sweep now share one rule for who holds an issue, so a merged but still open issue's claim stops renewing, and the sweep logs issues merged by hand. ([#753](https://github.com/cbundy/dev-system/pull/753))
- **Bootstrap secrecy test no longer flakes** - The factory database bootstrap test now only checks its own processes for leaked secrets, so other suites running in parallel no longer fail it. ([#747](https://github.com/cbundy/dev-system/pull/747))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.39.0.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
