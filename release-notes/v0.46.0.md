## New

- **`/factory config` shows the loop's settings** - A new read-only op prints every setting the loop runs with, grouped (loop, capacity, limits, agents and gates, usage, config problems), and says where each value came from: default, repo, workspace, plugin, environment or an owner directive. ([#722](https://github.com/cbundy/dev-system/pull/722))
- **Each loop agent step gets its own scratch folder** - Every step's commands now run with `TMPDIR` pointing at a private folder outside the repo, cleaned up when the step ends, so temporary files no longer land in `/` or collide between agents. ([#723](https://github.com/cbundy/dev-system/pull/723))
- **Factory event reference and shared reader** - `npm run build:events` generates the factory event reference, a version lock and typed shapes from the event schemas, and lint fails while they are stale. ([#716](https://github.com/cbundy/dev-system/pull/716))

## Fixed

- **Restored Remote Control sessions no longer leave idle processes** - In server mode, a restart leaves the sessions the Remote Control server spawned for the server to reconnect, instead of starting extra reattach processes that took over its work. ([#718](https://github.com/cbundy/dev-system/pull/718))
- **`npm test` respects the container's CPU quota** - The test pool now sizes itself from the CPUs the container may use, not the host's count, so loop agents running tests no longer overload a workspace. ([#725](https://github.com/cbundy/dev-system/pull/725))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.37.1.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

- On an 8-CPU-quota workspace, confirm `scripts/test-pool.sh --check-jobs` reports 8, not the host count.
