## New

- **Evidence upload tool** - `callum-flow-evidence-upload` uploads screenshots and recordings to the repo's own private evidence storage and prints a signed link per file, and `dev-doctor` reports whether that storage is set up (docs/evidence-storage.md). ([#919](https://github.com/cbundy/dev-system/pull/919))
- **Old, new or shadow source for the factory read tools** - `callum-flow-evaluate`, `callum-flow-factory-state`, the claim tools' held rule and the factory HUD can each read the old event store, the new factory database, or both (shadow, the default), where they answer from the old store and record how the new one differed. ([#912](https://github.com/cbundy/dev-system/pull/912), [#913](https://github.com/cbundy/dev-system/pull/913), [#920](https://github.com/cbundy/dev-system/pull/920), [#924](https://github.com/cbundy/dev-system/pull/924))
- **Onboarding ends on the factory loop** - The onboarding guide and `onboard` skill now finish with the repo running on the factory loop: what the loop needs, creating its workspace, observe then act mode, and a first test issue. ([#921](https://github.com/cbundy/dev-system/pull/921))

## Changed

- **UI evidence goes through the upload tool** - Factory builders and fixers, `implement-issue` and the synced CLAUDE.md upload UI captures with `callum-flow-evidence-upload`, falling back to a capture committed on the branch when no storage is set up. ([#923](https://github.com/cbundy/dev-system/pull/923))
- **Metrics queries read the factory database** - The saved queries in docs/metrics.md read the factory event log instead of the old events table and the no-mistakes mirror. ([#910](https://github.com/cbundy/dev-system/pull/910))
- **New README** - The README is now a short landing page for the factory loop; the layer and image detail moved into the architecture doc. ([#930](https://github.com/cbundy/dev-system/pull/930))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.45.0.
- Factory database: after the restart `dev-doctor` reports the factory database as behind until `factory-db-bootstrap --db <name>` is re-run with the admin URL (migrations 0006 and 0007).
- Evidence storage: to use the upload tool, add each repo's container credentials as docs/evidence-storage.md describes; without them writers fall back to committed captures.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`.
