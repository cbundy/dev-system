## New

- **`/factory help config` lists every setting** - It shows each key `config set` accepts with its default and a one-line meaning, and a test keeps it in step with the loader and the docs. ([#1256](https://github.com/cbundy/dev-system/pull/1256))
- **A design can raise an issue in dev-system and wait for it** - When the owner has asked, or for a clear bug with evidence, the designer files the needed change in cbundy/dev-system once and the loop holds the design until that issue closes, instead of parking for the owner. ([#1257](https://github.com/cbundy/dev-system/pull/1257))
- **Release contents in the factory data** - The `factory.event_log` view now has `issues`, `issues_closed` and `headlines` columns for released events, and the Releases per week query reports issue counts and the first headline. ([#1255](https://github.com/cbundy/dev-system/pull/1255))

## Fixed

- **Owner notes keep their text as typed** - `/factory note` keeps inner spaces and line breaks, and a `resume N "note"` note accepts escaped quotes. ([#1253](https://github.com/cbundy/dev-system/pull/1253))
- **The sweep runs again on every loop** - Its default-branch lookup no longer fails, so the unrecorded-merges check runs and the `sweep stalled` alert stops. ([#1259](https://github.com/cbundy/dev-system/pull/1259))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref. Loop workspaces on the `orchestrator-loop` template pick up the plugin only after the foreman pushes that template (`coder/push.sh orchestrator-loop`).
- Base image: rebuild or re-pull the dev container to get image 2.70.0 (the sweep fix and the new event_log columns).
