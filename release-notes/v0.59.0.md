## New

- **A design wait can name another repo** - A designer can now wait on an issue closing or a release tag in another repo (for example a dev-system release), not only its own. The loop reads that repo's newest release and clears the wait once the condition holds. ([#990](https://github.com/cbundy/dev-system/pull/990))
- **The owner hears about a wait that cannot be read** - When a waiting issue's condition cannot be read for a whole waiting period (a failing read, or a repo with no release yet), the loop now tells the owner once per period with a `wait-unreadable` item instead of the quiet daily note. ([#1001](https://github.com/cbundy/dev-system/pull/1001))
- **Shadow compare for the loop's facts** - The `eventsSource` setting now also picks where the loop reads its facts and rebuilds a lost ledger. In the default `shadow` it still decides on the old store, compares with the new one at most hourly and tells the owner once per set of differences. ([#996](https://github.com/cbundy/dev-system/pull/996))

## Changed

- **Judge interventions are recognised** - The event log, its readers and `callum-flow-event` accept `who=judge` for an intervention, so a control op run by the loop's judge can be told apart from the owner's own. Nothing writes it yet. ([#1000](https://github.com/cbundy/dev-system/pull/1000))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.47.3.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Factory loop: if the facts shadow tells get noisy or the new read misbehaves, go back with `/factory config set eventsSource old`.
