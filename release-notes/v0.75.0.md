## New

- **Claim queue in factory-state** - `callum-flow-factory-state` now shows each repo's newest queue snapshot: its age, reason, free slots, the owner's controls and the top 10 candidates with their rank, score and why. A database that predates the snapshot columns shows `n/a` instead of failing. ([#1161](https://github.com/cbundy/dev-system/pull/1161))
- **Intake stamp settings, off by default** - New `intakeStamp`, `intakeModel` and `intakeAreas` settings and three queue score factors (factory area, needs owner, path overlap with in-flight work). Nothing changes in the claim order until `intakeStamp` is set to `on`; `/factory config` and the settings snapshot show the new values. ([#1160](https://github.com/cbundy/dev-system/pull/1160))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Base image: rebuild or re-pull the dev container to get the new `callum-flow-factory-state`.

## Verify

- Run `callum-flow-factory-state` and confirm each repo shows a `queue (...)` line and a `queue controls: ...` line, and the JSON has a `queue` key after `other_runs`.
- Run it with `--source old` and confirm `queue` is an n/a with its reason.
- Confirm `/factory config` lists `intakeStamp` (off), `intakeModel` (haiku), `intakeAreas` and the new `queueScore` factors.
- With `intakeStamp` off, confirm the claim order and reasons are unchanged and observe runs no git diff for in-flight paths.
