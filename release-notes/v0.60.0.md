## New

- **The loop says when the ready queue is starved** - When every ready issue is blocked and nothing is in flight for an hour (new `starvedNoticeAfterMs` setting), the loop tells the owner once per spell and day, naming each root blocker and why it is not moving, most-blocking first. ([#1023](https://github.com/cbundy/dev-system/pull/1023))
- **Ready and claimed events carry the issue's title, labels and parent** - Readers of the factory event log can see an issue's newest title, labels and parent epic without another GitHub call (migration 0009). ([#1024](https://github.com/cbundy/dev-system/pull/1024))

## Changed

- **Flake bugs are held to a reproduction and a stress run** - For an issue labelled `flaky`, the designer's brief, the builder and the reviewer now require reproducing the flake under load, fixing its cause and showing many consecutive passing runs, with no unexplained retry, skip or raised timeout. ([#1029](https://github.com/cbundy/dev-system/pull/1029))

## Fixed

- **Judge control-tool ops are logged as the judge's** - A pause, unpause or config change the judge makes through the control tool is now logged as a `who=judge` intervention; `/factory` ops stay the person's. ([#1003](https://github.com/cbundy/dev-system/pull/1003))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.48.0.
- Factory database: after the restart `dev-doctor` reports the factory database as behind until `factory-db-bootstrap --db <name>` is re-run with the admin URL (migration 0009).
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
