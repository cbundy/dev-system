## New

- **Dry-run the intake reader with `/factory stamp <N>`** - The owner (or an agent, like `status`) can run the loop's new intake reader on one issue and see what it would decide, even while `intakeStamp` is off or the loop is in observe mode. It writes nothing to GitHub, the queue or the event log; the answer arrives as one notice ending `dry run: nothing written`. ([#1207](https://github.com/cbundy/dev-system/pull/1207))

## Fixed

- **Milestone state events are recorded again** - The loop's `milestone_state` events were refused because they had no `last_tag`. The loop now carries the newest release tag, so the event is always well formed, and the `released` log entry can fire once per tag. ([#1208](https://github.com/cbundy/dev-system/pull/1208))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

## Verify

- Run `/factory stamp <N>` on an open issue with `intakeStamp` off and confirm the immediate reply names the model, then one notice ending `dry run: nothing written` arrives.
- Run it twice on the same issue at once and confirm the second answers `already stamping #N`.
- Confirm the stamp left no label, comment or event on the issue.
- Confirm the loop's `milestone_state` events are accepted and carry `last_tag`.
