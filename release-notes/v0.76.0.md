## New

- **Claim queue recorded as events** - The factory loop now writes the claim queue it saw on each pass as a `queue_snapshot` event: every candidate with its rank, score and why, plus free slots and the owner's controls. It writes at most once a minute while the queue changes, every 15 minutes when it is quiet, and at once on a pass that claims. ([#1164](https://github.com/cbundy/dev-system/pull/1164))
- **Intake stamp and observe-time columns** - The factory event log gains the `intake_stamp` event type and four optional observe-time fields on `loop_passes`, with metrics queries for each in `docs/metrics.md`. Nothing writes them yet; later releases add the producers. ([#1163](https://github.com/cbundy/dev-system/pull/1163), [#1167](https://github.com/cbundy/dev-system/pull/1167))

## Changed

- **Faster PR reads in the loop** - The factory loop reads the PRs due on a pass up to 4 at once instead of one by one, in the same order and within the same rate-limit budget. Each pass also measures how long observing took and how much of it went to commands, shown in the trace. ([#1166](https://github.com/cbundy/dev-system/pull/1166))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Base image: rebuild or re-pull the dev container to get the new factory database migrations and translator.

## Verify

- After a few minutes of the loop running, confirm `queue_snapshot` events appear for the repo and `callum-flow-factory-state` shows a fresh queue line.
- Confirm no `queue snapshot: write failed` problem shows in the loop's pass lines.
- Run `dev-doctor` and confirm the factory database check passes at schema version 25.
- With trace on, confirm each trace record carries an `observe` field with `ms`, `commandsMs` and `inProcessMs`.
- Confirm the loop still reads PRs in the same order and stops starting new reads once a rate limit is met.
