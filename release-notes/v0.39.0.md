## New

- **Factory loop v2, opt-in per repo** - A simpler factory loop: every issue has one explicit state, shown as a `factory:*` label; the loop runs a one-at-a-time merge queue itself and keeps no-mistakes out of its path; every agent works only in its own worktree slot. A repo turns it on with `planner: v2` in the loop's config. The default stays v1, which is no longer maintained. ([#638](https://github.com/cbundy/dev-system/pull/638))
- **Companion plugin `factory-loop-workspace`** - Starts each loop agent in its slot. It refuses writes outside the slot, pushes to other branches and background commands, and runs the repo's lint and tests before an agent may finish. Only the loop workspace template turns it on. ([#638](https://github.com/cbundy/dev-system/pull/638))
- **Reconcile tool and lives cap** - `factory-reconcile` clears stale claims, and an issue that fails three times is marked `factory:rejected` until the owner retries it. ([#638](https://github.com/cbundy/dev-system/pull/638))
- **Up to 16 CPUs per workspace** - A dev-system workspace can ask for up to 16 CPUs, up from 8. ([#637](https://github.com/cbundy/dev-system/pull/637))

## Changed

- **CLAUDE.md names two ways of working** - A new synced section separates loop agents, which follow their prompt and never run no-mistakes or lease worktrees, from the manual path for people and interactive sessions. Guard messages now say which path they mean. ([#638](https://github.com/cbundy/dev-system/pull/638))
- **Claims and the sweep follow the event log** - A claim ends when its life ends. A dropped issue is never put back in the queue. The `In development` label is no longer set. ([#638](https://github.com/cbundy/dev-system/pull/638))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.33.0, together with the plugin update.
- Plugin, CLI and templates: `npm update @callum/dev-system && npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`.
- To try v2 in a repo, add `.claude/factory-loop.json` with its `gateCommands`, then set `planner: v2` in the loop workspace's config.
