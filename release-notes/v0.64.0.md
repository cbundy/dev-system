## New

- **The loop logs the state of main** - The factory loop now reads main's head, its workflow runs and its deployments every 5 minutes (new `mainEveryMs` setting) and writes a `main_state` event each time that state changes. Queue behaviour is unchanged. ([#1080](https://github.com/cbundy/dev-system/pull/1080))
- **The loop logs where it asked its question** - After it posts a park question or a wait comment, the loop writes a `comment_posted` event with the comment's link. ([#1081](https://github.com/cbundy/dev-system/pull/1081))
- **Settings in force per worker** - New `settings_changed` event type and a `config` column on `factory.workers` (migration 0015). Each heartbeat now writes the factory loop's settings snapshot there, and docs/metrics.md gains a Settings section to query it. ([#1072](https://github.com/cbundy/dev-system/pull/1072), [#1084](https://github.com/cbundy/dev-system/pull/1084))
- **Permission prompt events** - New `prompt_denied` and `prompt_waiting` event types, their view columns (migration 0014) and a Permission prompts query in docs/metrics.md. Nothing writes them yet. ([#1069](https://github.com/cbundy/dev-system/pull/1069))

## Changed

- **One full test run per machine** - A full `npm test` now waits while another full run holds the machine, and concurrent runs share the CPUs. Loop agents run only the test subsets they change and leave the full gate to the stop gate. ([#1076](https://github.com/cbundy/dev-system/pull/1076))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.52.0. A loop workspace with the migrator secret applies migrations 0014 and 0015 itself at start-up.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update` brings the updated CLAUDE.md wording for loop agents' test runs.
