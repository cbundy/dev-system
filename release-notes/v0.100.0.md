## New

- **The factory commands have fabriek names** - Every factory command in the base image is now `fabriek-<x>` (for example `fabriek-issue-read`, `fabriek-event`, `fabriek-merge`), and every setting can be given as `FABRIEK_<X>`. The old `callum-flow-<x>` commands stay as aliases with the same output and exit codes, and the old `CALLUM_FLOW_<X>` settings still work; `FABRIEK_<X>` wins when both are set. The old names are kept for 10 minor releases. ([#1362](https://github.com/cbundy/dev-system/pull/1362))
- **The shared plugin is now fabriek** - The callum-flow plugin is renamed fabriek, and its skills name the `fabriek-*` commands. The marketplace keeps a `callum-flow` entry with the same content for 10 minor releases, so repos that enable `callum-flow@callum` keep working. The image now installs `fabriek@callum` by default, replaces an old `callum-flow` install with it, and falls back to `callum-flow@callum` when a repo pins a release older than the rename. `dev-doctor` warns when both names are installed or enabled. ([#1363](https://github.com/cbundy/dev-system/pull/1363))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A repo can switch `callum-flow@callum` to `fabriek@callum` in its `.claude/settings.json`; enable only one of the two. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).
- Base image: rebuild or re-pull the dev container to get image 2.79.0, which brings the `fabriek-*` commands, the `FABRIEK_<X>` settings and the plugin twin handling.

## Verify

- On image 2.79.0, confirm `fabriek-issue-read --help` and `callum-flow-issue-read --help` print the same output and exit 0.
- Confirm `CALLUM_FLOW_REPO` alone still sets the repo for `fabriek-event`, and `FABRIEK_REPO` wins when both are set.
- In a repo with no plugin settings, confirm `dev-init --plugins` installs only `fabriek@callum`.
- In a workspace that had `callum-flow@callum` installed and does not enable it, confirm `dev-init --plugins` prints `replaced Claude plugin callum-flow@callum with fabriek@callum`.
- In a repo that enables `callum-flow@callum`, confirm only `callum-flow@callum` is installed and `dev-doctor` does not warn.
- Confirm `dev-version` reports the plugin version for either plugin name.
- Confirm a loop on the new release still claims, reviews and merges through the old `callum-flow-*` aliases.
