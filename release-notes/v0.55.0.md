## New

- **Dependency chain skill** - `/dependency-chain` maps an issue's, or an area of work's, full chain of sub-issues and blockers as a clickable doc that shows what is stuck and who has to act. ([#948](https://github.com/cbundy/dev-system/pull/948))
- **Batched issue reads** - `callum-flow-issue-read --issues N,N,...` reads many issues in one GitHub request, and the factory loop now reads each pass's due issues with it, so idle passes with a large queue are much faster. ([#933](https://github.com/cbundy/dev-system/pull/933))
- **Old, new or shadow source for heartbeat-state** - `heartbeat-state` can read the old event store, this device's new factory event log, or both (shadow, the default), where it answers from the old store and records how the new one differed. ([#935](https://github.com/cbundy/dev-system/pull/935))

- **Priority label for claims** - The factory loop claims issues carrying the `priority` label (set with `priorityLabel`) after the owner's list and before the rest of the queue; `/factory config` shows the new Claims group. ([#940](https://github.com/cbundy/dev-system/pull/940))

## Changed

- **The loop always plans with v2** - The v1 planner is gone. A loop settings file that still sets `planner` or `shadow` loads as before; the key is ignored and reported in the config view. ([#936](https://github.com/cbundy/dev-system/pull/936))

## Fixed

- **Queued stop gates no longer cut off** - A builder or fixer whose stop gate waited more than 10 s for its turn was let go with an unknown gate result; it now waits for its turn and runs the gate. ([#934](https://github.com/cbundy/dev-system/pull/934))

- **Factory events carry the session id** - `callum-flow-event` now also reads `CLAUDE_CODE_SESSION_ID`, so events written inside a Claude session record which session wrote them instead of none. ([#941](https://github.com/cbundy/dev-system/pull/941))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.46.0. The loop falls back to one-at-a-time issue reads on an older image.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Loop settings: remove any `planner` or `shadow` key from `.claude/factory-loop.json` to clear the config view's notice.
