## Changed

- **no-mistakes pinned to v1.97.0** - The base image now installs exactly no-mistakes v1.97.0 and the build fails on any other version. Every workspace was stuck on v1.84.0 because upstream's "latest" release never moved. ([#605](https://github.com/cbundy/dev-system/pull/605))
- **Loop and skills work with no-mistakes v1.97** - A PR that should close its issue now asks for it explicitly when the run starts (`--closes`), and partial fixes name the review findings they decline (`--ignore`). Ship this plugin together with base image 2.32.0. ([#605](https://github.com/cbundy/dev-system/pull/605))

## Fixed

- **Evidence stays out of PR bodies** - The synced pipeline config now uses the minimal PR appendix: one risk line and the pipeline's signature, no test transcripts. This fixes the factory loop's PR body byte-compare and size-limit failures. ([#605](https://github.com/cbundy/dev-system/pull/605))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.32.0. Do this together with the plugin update; the new plugin expects no-mistakes v1.97.0.
- Plugin, CLI and templates: `npm update @callum/dev-system && npx callum-dev update`, commit the `.claude/settings.json` and `.no-mistakes.yaml` it produces, then restart the container or run `dev-init --plugins`.

## Verify

- Confirm `no-mistakes --version` reports v1.97.0 in a container built from base image 2.32.0.
- Confirm a PR opened by the pipeline on 0.38.0 has a minimal appendix with no test transcripts.
- Confirm a PR that should close its issue still lists it under closing issue references.
