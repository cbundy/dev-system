## New

- **The loop stamps ready issues with the intake reader** - With `intakeStamp` on, the loop now runs the intake reader for real on each ready, trusted issue, at most two at a time and once per body version, so an edited issue is read again once. A good answer sets the issue's `area:*` label and `needs-decision` when the owner must decide; labels the owner changed are left alone. Each try writes one `intake_stamp` event with its token totals, and four new metrics queries show its cost, failures and labels. With the switch off (the default) nothing changes. ([#1209](https://github.com/cbundy/dev-system/pull/1209))

## Fixed

- **Dual-write check no longer fails on new-only events** - Event types the old store never had, such as `gate_run`, are now reported as `new-only` lines instead of extras, so they no longer turn the verdict `DIFFERENT`. ([#1211](https://github.com/cbundy/dev-system/pull/1211))
- **Factory readers tolerate events they do not know** - `callum-flow-factory-state`, `callum-flow-evaluate` and the heartbeat no longer fail when a newer writer logs an event type or version they do not know: they leave it out and list it under `skipped_events`. ([#1212](https://github.com/cbundy/dev-system/pull/1212))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Base image: rebuild or re-pull the dev container to get the `body_sha` field in `callum-flow-issue-read` (intake stamping needs it) the fixed dual-write check and the tolerant factory readers.

## Verify

- Run `callum-flow-issue-read --json --issues` and confirm each item carries a 16-hex `body_sha` and no body.
- With `intakeStamp` off, confirm the loop plans no intake-stamp runs and writes no labels or events.
- With `intakeStamp` on, confirm a ready issue gets one stamp, an `area:*` label, and one `intake_stamp` event with token totals.
- Edit that issue's body and confirm it is stamped once more, and not again after that.
- Change a label the loop set and confirm the next stamp keeps the owner's choice.
- Run `callum-flow-dual-write-check` on a window with `gate_run` events and confirm it prints `new-only gate_run: N` and an `OK` verdict.
- Run `callum-flow-factory-state --source new --json` against a log holding an unknown event version and confirm it exits 0 and lists it in `skipped_events`.
