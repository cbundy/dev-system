## New

- **Factory database setup is documented and checked** - A new guide, `docs/factory-db.md`, walks through standing up the factory database from a fresh Postgres server. Workspaces get their own writer and reader connection secrets, and `dev-doctor` now checks each one: reachable, logged in as the right role, and on the image's schema version. It only warns while nothing is configured. ([#709](https://github.com/cbundy/dev-system/pull/709))

## Fixed

- **PRs no longer merge before all of their CI has started** - The loop and the merge guard now count a workflow run that has no check yet (for example one queued behind another run) as pending CI, so a PR whose visible checks are all green waits for it instead of merging early. ([#715](https://github.com/cbundy/dev-system/pull/715))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.37.0, together with the plugin update.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

## Verify

- Run `dev-doctor` on a workspace with no factory database secrets and confirm it warns, naming both secret files and the doc.
- Follow `docs/factory-db.md` against a scratch Postgres and confirm `dev-doctor` reports both factory database checks OK.
- Open a PR whose workflow waits on a concurrency group and confirm the loop does not merge it while that run is queued.
