## New

- **Orchestrator (loop) Coder template** - A third template runs a repo's orchestrator with the factory loop instead of the issue-orchestrator skill: the session starts as the loop's judge and needs no watcher re-armed after a restart. The loop starts in observe mode and acts only once act mode is set. ([#578](https://github.com/cbundy/dev-system/pull/578))
- **factory-loop in the marketplace** - The loop plugin can now be installed from the `callum` marketplace. It is enabled nowhere by default; the new template asks for it. ([#578](https://github.com/cbundy/dev-system/pull/578))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref. Required before a repo can use the Orchestrator (loop) template.
- Coder: push the new template from main with `coder/push.sh orchestrator-loop`; the existing templates are unchanged.

## Verify

- Create a workspace from Orchestrator (loop) on a repo updated to 0.37.0 and confirm `claude plugin list` shows factory-loop and callum-flow at v0.37.0.
- Confirm its session is named with the loop name format and its first message ran `/factory-loop:judge`.
- Confirm the loop's decision log appears under `/persist/claude/factory-loop/` with `executed: false` (observe mode).
