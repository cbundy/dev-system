## Changed

- **Repos and Coder workspaces move to the fabriek name** - `npx callum-dev update` now enables `fabriek@callum` instead of `callum-flow@callum`, drops a leftover `callum-flow@callum` entry so only one name is ever enabled, and allows the `fabriek-*` commands next to the old `callum-flow-*` ones. Coder workspaces set `FABRIEK_TRUSTED_AUTHORS` as well as the old `CALLUM_FLOW_TRUSTED_AUTHORS`, the loop template installs `fabriek@callum`, and the docs use the fabriek names. The devcontainer still forwards `CALLUM_FLOW_TRUSTED_AUTHORS` from the host, so nothing changes in how you set it. ([#1366](https://github.com/cbundy/dev-system/pull/1366))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces (it switches `callum-flow@callum` to `fabriek@callum`), then restart the container or run `dev-init --plugins`. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`.

## Verify

- In a repo that enables `callum-flow@callum`, run `npx callum-dev update` and confirm `.claude/settings.json` enables only `fabriek@callum` and allows both the `fabriek-*` and `callum-flow-*` commands.
- In a repo with no baseline, confirm the same update leaves only `fabriek@callum` enabled.
- In a fresh Coder workspace, confirm `FABRIEK_TRUSTED_AUTHORS` and `CALLUM_FLOW_TRUSTED_AUTHORS` are both set to the same value and `dev-doctor` passes.
- On a loop workspace stop, confirm the wind-down emits its `wind_down` event through `fabriek-event`.
- Confirm a loop on `orchestrator-loop` pushed at this release installs `fabriek@callum` and still claims, reviews and merges.
