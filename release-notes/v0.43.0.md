## New

- **One command sets up a factory database** - `factory-db-bootstrap --db NAME` creates a factory database from scratch on any Postgres server: an owner, a writer and a reader role, the events and workers tables, and versioned migrations. Running it again changes nothing. The admin URL and passwords are never printed or passed on the command line. ([#702](https://github.com/cbundy/dev-system/pull/702))
- **`/factory` shows its options as you type** - The command now shows a short list of its ops as a placeholder, and `/factory help` answers with the full help page instead of an error. ([#703](https://github.com/cbundy/dev-system/pull/703))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.35.0 to get `factory-db-bootstrap`.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

## Verify

- In a container on base image 2.35.0, run `factory-db-bootstrap --db factory_rc` twice against a scratch Postgres and confirm the second run reports no changes.
- Confirm the writer role cannot DELETE from factory.event_store and the reader role can only SELECT.
- Type `/factory ` and confirm the options placeholder appears; run `/factory help` and confirm it prints the help page.
