## New

- **Release candidate groundwork** - Release notes gain a Verify checklist for checking a candidate, a candidate and its final release list the same changes, and milestones refuse candidate versions ([#444](https://github.com/cbundy/dev-system/pull/444))
- **Run a candidate plugin version** - `DEV_CANDIDATE_PLUGIN_REF` points a workspace's callum-flow plugin at a candidate tag, and `dev-version` shows it as a candidate instead of stale ([#447](https://github.com/cbundy/dev-system/pull/447))

## Changed

- **Gate models per step** - No-mistakes reviews and review fixes run on Claude Opus with no fallback. Other steps run on Codex first with Claude Sonnet as fallback, models are pinned by ID, and the Codex priority tier is dropped to save credits ([#446](https://github.com/cbundy/dev-system/pull/446))

## Fixed

- **Plugins kept on an unreleased pin** - A workspace pinned to a plugin version that is not tagged yet keeps its installed plugins and warns, instead of uninstalling them ([#447](https://github.com/cbundy/dev-system/pull/447))
- **Two flaky shell tests** - The event-log and watcher suites no longer fail at random under load ([#445](https://github.com/cbundy/dev-system/pull/445))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`.
- Base image 2.28.0: rebuild or re-pull the dev container.

## Verify

- `no-mistakes stats --run <id>` on a real gate run shows review and review fix on claude-opus-5-5, other steps on codex
- `dev-init` and `dev-doctor` print the agent order, models and review roles
- With `DEV_CANDIDATE_PLUGIN_REF` set to a missing tag, `dev-init --plugins` warns and keeps callum-flow installed
