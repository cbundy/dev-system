## New

- **Park questions with options to tick** - When the factory parks an issue for the owner, the comment now shows the decision, its context, lettered options and a recommendation. Tick one option and remove the `factory:parked` label, and the loop resumes with that choice. ([#813](https://github.com/cbundy/dev-system/pull/813))
- **Gate runs in the factory database** - The factory event log now carries gate run results, wait and run times and concurrency as columns, through database migration 0002. Nothing writes gate runs yet; this release ships the schema so the producer can follow. ([#817](https://github.com/cbundy/dev-system/pull/817), [#814](https://github.com/cbundy/dev-system/pull/814))

## Changed

- **Stop gates take turns** - A workspace now runs only a few stop gates at once (by default one per 8 CPUs, set with `gateConcurrency`), queued in order, so full test runs no longer starve each other into timeouts. `/factory config` shows the limit and its source. ([#814](https://github.com/cbundy/dev-system/pull/814))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.42.0.
- Factory database: after the restart `dev-doctor` reports the factory database as behind until `factory-db-bootstrap --db <name>` is re-run with the admin URL.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

- On base image 2.42.0, run `factory-db-bootstrap --db factory_rc` against a scratch Postgres at version 1 and confirm it upgrades to version 2 and a second run changes nothing.
- Query `factory.event_log` and confirm the result, wait_ms, run_ms, concurrency, queued_behind and started_at columns exist.
- Park a test issue with a structured question, tick one option, remove the label, and confirm the resume note names the chosen option.
- Run `/factory config` and confirm `gateConcurrency` shows its value and source.
