## New

- **The designer runs on the routed model** - The loop's design step now runs on the model `callum-flow-designer-route` picks, so a share of designs can go to Sonnet (`CALLUM_FLOW_DESIGNER_SONNET_PCT`) and be compared in a new designer model query in docs/metrics.md. Routing never blocks design: on any failure the designer runs on the issue's `model:` label or its own model and the loop logs a fallback. With the variable unset, nothing changes. ([#1102](https://github.com/cbundy/dev-system/pull/1102))

## Changed

- **Release decisions survive translation** - The old-log translator now keeps a task wake's decision, and a new `reason=` token as its reason, on the `loop_entry` event, so older release reviews show what was decided and why. ([#1100](https://github.com/cbundy/dev-system/pull/1100))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.54.1.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

- With `CALLUM_FLOW_DESIGNER_SONNET_PCT` unset, let the loop design an issue and confirm the designer runs on its usual model and a `designer_routed` event is written.
- Set `CALLUM_FLOW_DESIGNER_SONNET_PCT=100` and confirm the next design runs on Sonnet.
- On base image 2.54.1, translate an old log with a `kind=task ... out=wake decision=hold reason=...` line and confirm `loop_entry` carries the decision and reason.
