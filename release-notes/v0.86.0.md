## New

- **The loop tells you when the image readers lag behind it** - When the image's factory readers skip events a newer loop writes, the owner now gets a `reader-behind` item naming the event types and count, once per set of types. If the skipped events matter to what the loop derives, the loop goes blind instead of claiming or releasing on partial data. ([#1214](https://github.com/cbundy/dev-system/pull/1214))

## Changed

- **Blind is now an owner item with its reason** - A blind loop is counted in the title, is told before other wakes, and its message carries the error that made it blind, so you know what to fix. The judge skill says what to do for each cause. ([#1214](https://github.com/cbundy/dev-system/pull/1214))
- **New event types roll out three minor releases behind their schema** - The designer, builder and reviewer agents now hold a producer of a new event type or version until the readers of the last three minor releases can read it, so a newer loop does not leave older images blind. ([#1216](https://github.com/cbundy/dev-system/pull/1216))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

## Verify

- Run the loop against an image whose readers report non-derived `skipped_events` and confirm one `reader-behind` owner item names the types and count, and is not repeated for the same set.
- Run it against a report with derived skips and confirm the loop goes blind, does not claim or release, and the blind tell carries the reader error.
- Confirm a blind loop shows in the title count and its tell goes out before other wakes.
- Run it against an older image with no `skipped_events` field and confirm the pass works as before.
