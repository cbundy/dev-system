## New

- **UI capture tool in the base image** - `callum-flow-capture` starts a repo's app on a free port, takes desktop and narrow full-page screenshots (and an optional video) with headless Chromium, stops the app on every exit and can upload the captures as PR evidence. The image ships the tool only; a UI repo adds Playwright and Chromium to its own dev image (see the base image README). ([#1285](https://github.com/cbundy/dev-system/pull/1285))
- **A UI capture policy for every repo** - The new `uiCapture` repo setting names the capture command builders and fixers run for a visible change, or `none` when a repo has no capture tooling, so a missing capture is at most a review warning. Onboarding now decides it for every repo, and design briefs test UI changes with that command instead of a manual dev server. ([#1284](https://github.com/cbundy/dev-system/pull/1284), [#1291](https://github.com/cbundy/dev-system/pull/1291), [#1296](https://github.com/cbundy/dev-system/pull/1296))
- **Each issue's live loop state in the factory DB** - New `factory.issue_state` view (and `issue_state_at` for any past moment) gives every issue's current factory loop state, with `factory.stuck_rules` flagging issues stuck too long. ([#1297](https://github.com/cbundy/dev-system/pull/1297))
- **Park on a repeated environment blocker** - A fixer can decline a finding it cannot do for lack of a tool, access or secret; a second such round in a row parks the issue with a question saying what the owner can provide. ([#1290](https://github.com/cbundy/dev-system/pull/1290))

## Changed

- **`callum-dev check` and `dev-doctor` require a UI capture policy** - A repo with the factory loop config whose CLAUDE.md does not say `n/a - no UI` now fails the check until it sets `uiCapture` or adds the `.callum-dev/evidence-off` marker. ([#1286](https://github.com/cbundy/dev-system/pull/1286))
- **Plain summaries in briefs and park questions** - Design briefs and owner questions open with a short plain summary, with the full technical text in a collapsed Details block. ([#1280](https://github.com/cbundy/dev-system/pull/1280))
- **v1 loop leftovers removed** - The factory-loop plugin no longer ships the v1 designer and adjudicator agents or the v1 answer contract. ([#1289](https://github.com/cbundy/dev-system/pull/1289))

## Fixed

- **Recovered merges keep their real merge time and title** - Merged events now carry GitHub's merge time and the issue or PR title, so hand merges recovered by the sweep no longer show as just merged and untitled. ([#1281](https://github.com/cbundy/dev-system/pull/1281))
- **Panel notifications no longer leak private repos** - Factory DB notifications now carry only an event id, so the public panel role cannot learn the repo, issue, type or device of rows it may not read. ([#1282](https://github.com/cbundy/dev-system/pull/1282))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`. Then set `uiCapture` in `.claude/factory-loop.json` (a capture command or `none`), or add `.callum-dev/evidence-off`, so `callum-dev check` passes.
- Base image: rebuild or re-pull the dev container to get image 2.72.0 (`callum-flow-capture`, `dev-doctor`'s UI capture check and factory DB migrations 0031 to 0033). Loops apply the migrations at their next start.
