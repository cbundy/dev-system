## Changed

- **Factory state comes from the factory DB's state view** - `callum-flow-factory-state` now reads each issue's state, step, attempt and lease from the `factory.issue_state_at` view and its stuck rules, instead of working the state out from raw events. It no longer reads the no-mistakes mirror or the worker table, `--rule` takes a state name (S1 to S4 still work as aliases), and a factory DB not yet at migration 0033 makes it exit with a hint to run `factory-db-bootstrap --migrate`. ([#1299](https://github.com/cbundy/dev-system/pull/1299))
- **The loop, reconcile tool and HUD decide on the v2 state** - They read the v2 state each factory-state row reports (queued, designing, building, reviewing, fixing, merge-queue, parked, waiting, closed) instead of the old stage words, and fall back to the stage for a report from an older image. Release reasons, ghost lines and requeued or abandoned events now hold the v2 state. ([#1301](https://github.com/cbundy/dev-system/pull/1301))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`.
- Base image: rebuild or re-pull the dev container to get image 2.73.0 (the view-based `callum-flow-factory-state`). Its factory DB must be at migration 0033, which a loop start applies.

## Verify

- On the new image, run `callum-flow-factory-state --repo cbundy/dev-system --github off --format json` and confirm each row carries `state`, `step`, `life` and `state_since`, and the states match `select * from factory.issue_state`.
- Confirm `callum-flow-factory-state --rule S5` exits 2 and `--rule S2` still works.
- Against a database at migration 0032, confirm the tool exits 1 and names 0033 and `factory-db-bootstrap --migrate`.
- With the new plugin, confirm the HUD counts and the loop's claims match the v2 states in the factory-state report.
- Run `factory-reconcile` and confirm it reports no false orphans on the new report shape.
