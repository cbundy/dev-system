## New

- **Releases cut in a repo's own CI reach the factory store** - A repo that releases from a GitHub workflow adds one step, `cbundy/dev-system/.github/actions/released-event`, which attaches the `released` event to the GitHub Release. Devices running the event push loop collect it and push it, so those releases show up in factory data. dev-system's own Release workflow now does this too. ([#1225](https://github.com/cbundy/dev-system/pull/1225))
- **Merged events record per-file line counts** - Each merged event now carries `file_lines`, the additions and deletions per file, so factory data can show where a change's size went. ([#1223](https://github.com/cbundy/dev-system/pull/1223))

## Changed

- **The dev image rebuilds after every base image publish** - `ghcr.io/cbundy/dev-system/dev` no longer lags a base image release by up to a week: a successful base publish now starts the dev image build. ([#1221](https://github.com/cbundy/dev-system/pull/1221))

## Fixed

- **The loop's title no longer flaps** - An empty ready list from GitHub that the issues' own labels contradict is held instead of accepted, and a sweep or heartbeat retry no longer drops its owner item while it runs, so the queue and owner counts stay steady. ([#1231](https://github.com/cbundy/dev-system/pull/1231))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Base image: rebuild or re-pull the dev container to get image 2.68.0.
