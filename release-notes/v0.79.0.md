## New

- **Token spend per agent step in the factory database** - Each finished agent step now records its input, output and cache tokens and its model, so the factory data can answer what each merged issue cost, per model and per step role. `docs/metrics.md` has ready-made queries for it. ([#1182](https://github.com/cbundy/dev-system/pull/1182))

## Changed

- **Faster loop passes** - The factory loop's sweep, heartbeat and session renames now run in the background, so a slow command or a rename that never answers no longer holds up a pass. Renames are capped at 10 seconds and a failed one is logged once. ([#1181](https://github.com/cbundy/dev-system/pull/1181), [#1183](https://github.com/cbundy/dev-system/pull/1183))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Base image: rebuild or re-pull the dev container to get the new factory database migration.

## Verify

- Let an agent step finish and confirm its `loop_entry` row in `factory.event_log` has token counts and a model.
- Run the "Tokens per merged issue" queries from `docs/metrics.md` and confirm they return sensible figures.
- Confirm `dev-doctor` reports factory database schema version 26.
- Watch a few loop passes and confirm sweep and heartbeat show as running off the pass, with pass times well under 20 s.
- Confirm the session title still updates as the loop moves between states.
