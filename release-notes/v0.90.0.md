## New

- **Clear an owner note with `note off`** - `/factory note N off` clears an issue's note and `/factory note off` clears the fleet note. ([#1250](https://github.com/cbundy/dev-system/pull/1250))

## Changed

- **An owner note replaces the earlier one** - A new note for an issue, or for the fleet, replaces the previous note of that scope instead of adding to it, and agents see only the newest. ([#1250](https://github.com/cbundy/dev-system/pull/1250))
- **The release hold lasts as long as the bump PR's CI** - The merge queue now holds while the bump PR's checks run, up to 45 minutes from each push, so main no longer moves ahead of it. A failed check ends the hold, and a hold that runs out tells the owner. ([#1245](https://github.com/cbundy/dev-system/pull/1245))
- **One release review per hour** - The loop starts at most one release review per UTC hour and none while one is still running. A wait that arrives later joins the running review or the next hour's, rather than starting another review within the hour. ([#1249](https://github.com/cbundy/dev-system/pull/1249))
- **A designer's merge brief is checked against the issue's Run it heading** - The loop refuses a brief that says merge for an issue with a `## Run it` heading when the designer answers, not first when the PR opens. ([#1244](https://github.com/cbundy/dev-system/pull/1244))
- **The release guide says when the loop workspaces need a template push** - A release that changes the plugin ends its report with the `orchestrator-loop` template push the foreman runs. ([#1252](https://github.com/cbundy/dev-system/pull/1252))

## Fixed

- **Repos with capital letters are no longer blind to the factory report** - The loop matches the factory report's repo case-insensitively, and an unusable report now gives a clear reason. ([#1251](https://github.com/cbundy/dev-system/pull/1251))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref. Loop workspaces on the `orchestrator-loop` template pick up the plugin only after the foreman pushes that template (`coder/push.sh orchestrator-loop`).
