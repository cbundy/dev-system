## New

- **One GitHub token can be a workspace's only identity** - With `DEV_GH_TOKEN_FILE` set, a workspace logs `gh` and git in with that token alone, replacing any other login, and trusts the token's account as an issue author. `dev-doctor` reports the identity in use and fails when the token is missing or rejected. ([#736](https://github.com/cbundy/dev-system/pull/736))
- **Run one test suite through the real entrypoint** - `npm test -- <id>...` runs only the named suites, with the same sandbox and PostgreSQL setup as a full run, so debugging one failing test no longer means re-running everything. The CLAUDE.md template now asks each repo to name its own single-suite command. ([#735](https://github.com/cbundy/dev-system/pull/735))
- **Factory event translator** - The base image ships a translator from today's event log lines to the new factory event format, including a new `loop_passes` event for the loop's per-minute pass summary. Nothing uses it yet. ([#737](https://github.com/cbundy/dev-system/pull/737))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.38.0.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`, then fill in the new single-suite line in CLAUDE.md.

## Verify

- On a workspace with `DEV_GH_TOKEN_FILE` set, confirm `gh auth status` shows only the token account and `dev-doctor` names it as the effective trusted author.
- Run `npm test -- <one node test file id>` and confirm only that job runs, with PostgreSQL available.
- Run `npm test -- nosuch` and confirm one error line and exit 2.
- Feed a `loop kind=passes` line to the translator and confirm it becomes a `loop_passes` event.
