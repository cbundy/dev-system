## New

- **The loop migrates the factory database at start-up** - A workspace with the migrator secret runs the new `factory-db-migrate` before the loop starts, bringing the schema up to the image's version. If the migrate fails or times out, the loop stays in observe and tells the owner once. ([#1055](https://github.com/cbundy/dev-system/pull/1055), [#1059](https://github.com/cbundy/dev-system/pull/1059))
- **Release events in the factory log** - New `released` and `milestone_state` events, the judge's decision on `loop_entry`, and release columns on `factory.event_log` (migration 0010), with new release queries in docs/metrics.md. ([#1058](https://github.com/cbundy/dev-system/pull/1058))
- **A claim records its score** - The claimed event can carry the claim rule's score and the factors behind it. ([#1054](https://github.com/cbundy/dev-system/pull/1054))
- **The settings in force, on disk** - Every observing pass writes the loop's settings, where each one came from and any config problems to `settings.json` in the loop directory. ([#1061](https://github.com/cbundy/dev-system/pull/1061))
- **Dependency facts for scoring** - The issue reader and the loop now carry each issue's blocking, blocked-by and parent lists and its newest ready time. No claim behaviour changes yet. ([#1052](https://github.com/cbundy/dev-system/pull/1052))

## Fixed

- **A split child that needs the owner is asked, not silent** - When a split makes a child the designer marks not ready, the loop now parks it on its open decision, so the owner sees the question and can resume it. ([#1057](https://github.com/cbundy/dev-system/pull/1057))
- **Tests no longer touch the real databases** - The test sandbox redirects the secrets directories and guards `psql`, so a test run can no longer write a real heartbeat that stops the loop acting. ([#1060](https://github.com/cbundy/dev-system/pull/1060))

## Upgrade

- Factory database: adopt the existing server once with the bootstrap command in docs/factory-db.md ("Adopt an existing server"), which writes the migrator URL file to `/etc/dev-system/migrator`. After that the loop applies migration 0010 itself at start-up.
- Coder template: push all three templates (`coder/push.sh dev-system`, `orchestrator`, `orchestrator-loop`) so `orchestrator-loop` mounts the migrator secret.
- Base image: restart workspaces (or rebuild the dev container) onto base image 2.50.0.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
