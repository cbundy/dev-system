## Breaking

- **Old watchers and v1 helper tools are gone from the image** - `orchestrator-watch.sh`, `pipeline-watch.sh`, `callum-flow-regate`, `callum-flow-fix-linkage` and `callum-flow-design-route` are removed, and synced settings no longer allow them. `callum-flow-merge-guard` keeps only its `--patch` mode: `--run` and `--update-behind` now exit 2 with a usage line. Nothing the factory loop runs used them. ([#1314](https://github.com/cbundy/dev-system/pull/1314))

## New

- **Merge train (off by default)** - With the new `mergeTrain` setting on, the merge queue tests the next approved PR on a `factory-train/*` branch while the head is still in CI, and merges it right after the head with no update and CI run of its own, as long as the tested tree still matches. Any mismatch drops the train and the PR takes the usual path. With the setting off, the queue behaves as before. ([#1321](https://github.com/cbundy/dev-system/pull/1321))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update` (drops the removed tools from the synced allowlist).
- Base image: rebuild or re-pull the dev container to get image 2.75.0. Scripts that call the removed tools or `callum-flow-merge-guard --run` / `--update-behind` must move to `--patch`.
- Merge train: to turn it on, first turn off "Require branches to be up to date before merging" in main's branch protection while keeping the `ci` check required, then set `"mergeTrain": true` in `.claude/factory-loop.json` (or `/factory config set mergeTrain true`). `/factory config` shows `mergeTrain on`.

## Verify

- On the new image, confirm `orchestrator-watch.sh`, `pipeline-watch.sh`, `callum-flow-regate`, `callum-flow-fix-linkage` and `callum-flow-design-route` are not on PATH.
- Run `callum-flow-merge-guard <pr> --run x` and confirm it exits 2 with one usage line and no gh call; `--patch` still verifies.
- With the new plugin and `mergeTrain` off, confirm `/factory config` shows `mergeTrain off` and the queue merges as before.
- With `mergeTrain` on and two approved PRs queued, confirm a `factory-train/i<N>-<tree7>` branch is pushed, CI runs on it, the second PR merges right after the head with `--tested-tree`, and the train branch is deleted.
- Confirm a train that goes stale (head moved or conflict) drops and the PR falls back to its own update and CI.
