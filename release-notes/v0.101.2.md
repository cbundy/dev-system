## Fixed

- **Slots with a huge untracked file free cleanly** - Freeing or preparing a slot no longer fails forever when the slot holds a very large untracked file such as a multi-GB core dump. Untracked files over 50 MB and core dumps are left out of the saved leftovers, named in the slot outcome and removed, and the owner is told once when freeing a slot gets stuck (`/factory retry N` clears it). ([#1377](https://github.com/cbundy/dev-system/pull/1377))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A loop workspace on the `orchestrator-loop` template picks up the plugin only after that template is pushed at this release (`coder/push.sh orchestrator-loop`).

## Verify

- Confirm ordinary untracked leftovers under 50 MB are still saved to the patch file and applied back.
