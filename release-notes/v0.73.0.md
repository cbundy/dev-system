## New

- **Gate memory is recorded** - The stop gate samples container memory while it runs and records the start, peak and limit on each `gate_run` event, as new `factory.event_log` columns (migration 0022). docs/metrics.md section 2e shows the memory each gate adds by repo and concurrency. ([#1154](https://github.com/cbundy/dev-system/pull/1154))
- **Queue snapshot event** - A new `queue_snapshot` event describes the loop's ranked claim queue (candidates, scores, why each is or is not claimable, free slots), with its `factory.event_log` columns (migration 0023) and queries in docs/metrics.md. Nothing writes it yet. ([#1155](https://github.com/cbundy/dev-system/pull/1155))

## Changed

- **Conflicts get their own fix cap** - Fix rounds caused by other merges (a conflict, or red CI in the merge queue) now count against a separate cap, `conflictFixCap` (default 5), instead of the shared review fix cap, so a PR is no longer parked just because main kept moving. The triage prompt and `/factory config` show the new count and setting. ([#1153](https://github.com/cbundy/dev-system/pull/1153))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.57.0. A loop workspace with the migrator secret applies migrations 0022 and 0023 itself at start-up.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

- On base image 2.57.0, start a loop workspace and confirm the status file reads migrated (or current) at schema version 23.
- Confirm a new `gate_run` row in `factory.event_log` has non-null `mem_start_bytes`, `mem_peak_bytes` and `mem_limit_bytes`.
- Confirm `/factory config` shows `conflictFixCap` with default 5.
- Confirm a PR that needs a conflict fix shows `conflicts=<n>` on its transition note and is not parked at the review fix cap.
