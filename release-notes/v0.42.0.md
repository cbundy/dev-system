## Changed

- **Split issues can wait on existing issues** - When the v2 factory loop splits an issue, a child can now be blocked by an existing open issue as well as by its siblings, so it is not claimed before the work it depends on lands. ([#699](https://github.com/cbundy/dev-system/pull/699))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

## Verify

- Have a designer split an issue with a child blocked by an open issue: the child is created with the blocked-by link and is not claimed while that issue is open.
- A child blocked by a closed issue is created unlinked, and the split summary names the closed issue.
