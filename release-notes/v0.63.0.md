## New

- **Record what a release carried** - The new `callum-flow-released <tag>` tool writes the `released` event for a release: its PRs, the issues it closed and its headlines, from one shared definition the release notes and milestone tools now use too. ([#1071](https://github.com/cbundy/dev-system/pull/1071))
- **Where a park's question was posted** - New `comment_posted` event type and a `comment_url` column on `factory.event_log` (migration 0011), with an example query for each parked issue's question link. ([#1062](https://github.com/cbundy/dev-system/pull/1062))
- **The state of main after a merge** - New `main_state` event type, its view columns (migration 0012) and two queries in docs/metrics.md: the newest state of each repo's main, and when main first and finally went green after each merge. ([#1068](https://github.com/cbundy/dev-system/pull/1068))
- **Flaky test fields** - `gate_run` and `intervention` events gain optional flake fields, `factory.event_log` gains their columns (migration 0013), and docs/metrics.md gains a Flaky tests section with per-flake and per-test queries. ([#1066](https://github.com/cbundy/dev-system/pull/1066))

## Changed

- **Readers know an issue closed as done** - The event readers and `callum-flow-factory-state` accept a closed transition whose reason is `done` (its work had already merged) and show it as merged. ([#1063](https://github.com/cbundy/dev-system/pull/1063))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.51.0. A loop workspace with the migrator secret applies migrations 0011 to 0013 itself at start-up.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
