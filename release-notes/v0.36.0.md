## New

- **Factory loop, ready for cutover** - A deterministic replacement for the issue orchestrator, shipped as the `factory-loop` plugin. Each minute it reads the factory's state, decides with tested rules, acts and records every decision; the model is woken only for judgment calls. Proven over six act-mode runs on a private testbed. It is not in the marketplace yet, so nothing changes for consumers until the cutover. ([#528](https://github.com/cbundy/dev-system/pull/528))
- **Live sessions and real context windows in factory data** - The worker heartbeat now reports which Claude sessions and sub-agents are running, and each session's actual context-window size, so dashboards no longer assume a 200k window. ([#508](https://github.com/cbundy/dev-system/pull/508))

## Changed

- **Watchers and event tools ready for the loop** - The pipeline and queue watchers gained a one-shot mode, and the event log gained a bookkeeping `loop` state that the existing tools ignore. Today's orchestrator is unaffected. ([#528](https://github.com/cbundy/dev-system/pull/528))

## Fixed

- **Implementer routing help** - `callum-flow-implementer-route --help` prints its usage and exits successfully instead of reporting a usage error. ([#529](https://github.com/cbundy/dev-system/pull/529))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`.
- Base image (2.31.0): rebuild or re-pull the dev container to get the watcher one-shot modes, the `loop` event state, live sessions in the heartbeat and the routing help fix.
