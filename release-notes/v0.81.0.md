## New

- **Optional regime on factory events** - Factory events can now record which regime produced them (`factory_loop_v2`, `testbed` or `manual`) in a new optional envelope field and database column. `callum-flow-event` takes it from `--regime` or `FACTORY_REGIME`; nothing sets it yet, so existing events read it as unknown. The push loop keeps working against a database that has not run the new migration. ([#1187](https://github.com/cbundy/dev-system/pull/1187))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Base image: rebuild or re-pull the dev container to get the updated event writer, translator and push loop.

## Verify

- Run the factory database migrations and confirm `factory.event_log` has a nullable `regime` as its last column and older rows read NULL.
- Write an event with `callum-flow-event --type ... --regime manual` and confirm its row carries `regime = manual`; without the flag or `FACTORY_REGIME`, confirm it is NULL.
- Against a database without the new migration, confirm the push loop still pushes lines, logs one stderr line and refuses nothing.
