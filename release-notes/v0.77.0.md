## Changed

- **Image tools write factory events natively** - The claim, sweep, merge, issue-read and implementer-route tools and the usage check now write their factory events straight to the new event store in its own shape, with the same type and data as before. The design-route, regate and pipeline-watch tools no longer log the states the event log never used, and `usage-check.sh` gains a `--to-data` mode that prints a reading as event data. ([#1172](https://github.com/cbundy/dev-system/pull/1172))
- **Factory loop writes its events natively** - The loop now writes its record events, ledger entries and minute pass summaries straight to the new event store. It no longer writes the `delegated`, `fix_requested` and `merge_ready` entries or the cap and breaker lines; cap and breaker behavior is unchanged. ([#1173](https://github.com/cbundy/dev-system/pull/1173), [#1174](https://github.com/cbundy/dev-system/pull/1174))

## Fixed

- **Claim holder time** - A claim's holder time no longer carries a stray `since ` prefix. ([#1172](https://github.com/cbundy/dev-system/pull/1172))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Base image: rebuild or re-pull the dev container to get the updated factory tools.

## Verify

- Claim an issue and confirm a `claimed` event appears in the new event store and nothing new lands in the old log.
- Run `callum-flow-factory-state` and confirm claims, merges and sweeps still show as before.
- After a few minutes of the loop running, confirm `loop_entry` and `loop_passes` events keep arriving for the repo.
- Confirm a merge by the loop still records a `merged` event with its issue.
- Run `usage-check.sh --to-data` on a reading line and confirm it prints the event data.
- Confirm no event write failures show in the loop's pass lines.
