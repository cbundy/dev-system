## New

- **Release planning in milestones** - In repos with a `Next release` milestone, the orchestrator puts release-blocking work in it as it goes, keeps the expected version bump current, names what the next release waits on, and moves merged issues that stay open (run-it, keep-open) to `Later` so they never block a release ([#455](https://github.com/cbundy/dev-system/pull/455))

## Upgrade

- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.

## Verify

- A merged issue that should block the release lands in `Next release` in the same orchestrator tick
- Asking the orchestrator "what is the next release waiting on" names the open milestone items, or says nothing blocks it
- A merged run-it issue moves to `Later` and stays open
