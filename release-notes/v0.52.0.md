## New

- **Wind-down mode** - The factory loop can wind down: it starts nothing new and lets running work finish, within `windDownMinutes`. A Coder workspace stop now winds the loop down before the container goes, when the template's `wind_down_minutes` is above 0 (10 for orchestrator-loop). Each wind-down is recorded as a `wind_down` event with saved queries. ([#847](https://github.com/cbundy/dev-system/pull/847), [#849](https://github.com/cbundy/dev-system/pull/849), [#845](https://github.com/cbundy/dev-system/pull/845))
- **Designers can wait** - A designer can park an issue in a waiting state on a checkable issue or PR condition, or until a release tag contains a commit; the loop re-checks it each pass and the event readers and factory state show it. ([#848](https://github.com/cbundy/dev-system/pull/848), [#850](https://github.com/cbundy/dev-system/pull/850), [#844](https://github.com/cbundy/dev-system/pull/844))
- **Gate runs with wait time** - Each stop gate run is now written as a `gate_run` factory event with its start time and how many runs it queued behind. ([#835](https://github.com/cbundy/dev-system/pull/835))
- **Worker machine stats** - Each worker heartbeat records CPU use and limits in the factory database (migration 0003), with 30 days of samples. ([#834](https://github.com/cbundy/dev-system/pull/834), [#820](https://github.com/cbundy/dev-system/pull/820))
- **Issue dependencies in the issue reader** - `callum-flow-issue-read` lists the issues that block an issue and those it blocks. ([#839](https://github.com/cbundy/dev-system/pull/839))
- **Docker host choice** - A Coder workspace can pick its Docker host from the template's `docker_hosts` list. ([#824](https://github.com/cbundy/dev-system/pull/824))

## Changed

- **v2 is the default planner** - A repo or workspace with no `planner` setting now runs the factory loop's v2 planner instead of v1. Set `"planner": "v1"` before pulling this release to stay on v1, which stays available as an explicit opt-in. ([#858](https://github.com/cbundy/dev-system/pull/858))
- **Onboarding is for the factory loop only** - `callum-dev init` no longer scaffolds no-mistakes or the PR template; it writes `.claude/factory-loop.json` and a CI workflow instead. Existing repos keep their no-mistakes files, now unsynced. ([#857](https://github.com/cbundy/dev-system/pull/857))
- **Designers explore with their own reads** - The v2 designer no longer spawns an explorer; it reads the code itself against a checklist. ([#852](https://github.com/cbundy/dev-system/pull/852))
- **Briefs make decisions observable** - Every design brief has an Observability section naming where each new decision is recorded and the query it answers. ([#853](https://github.com/cbundy/dev-system/pull/853))

## Fixed

- **No duplicate backfill events** - The dual-write backfill writes to the new event log only, so it no longer duplicates each record's last transition. ([#854](https://github.com/cbundy/dev-system/pull/854))
- **Tests under loop slots** - `npm test` works when TMPDIR is under /persist, and the heartbeat CPU test no longer fails on busy CI runners. ([#833](https://github.com/cbundy/dev-system/pull/833), [#834](https://github.com/cbundy/dev-system/pull/834))

## Upgrade

- Planner: any workspace meant to stay on v1 must set `"planner": "v1"` first; otherwise it runs v2 after the pull.
- Base image: restart workspaces (or rebuild the dev container) onto base image 2.43.0.
- Factory database: after the restart `dev-doctor` reports the factory database as behind until `factory-db-bootstrap --db <name>` is re-run with the admin URL (migrations 0003 and 0004).
- Coder: push the updated `dev-system` template (new `docker_hosts` and `wind_down_minutes` variables) and restart workspaces.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- CLI and templates: `npm update @callum/dev-system && npx callum-dev update`.
