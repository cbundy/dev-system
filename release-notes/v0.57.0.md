## New

- **Merges wait while a release bump PR runs CI** - The factory loop holds its own merges for up to 10 minutes from the moment a PR on the release branch prefix opens, so the bump PR no longer falls behind main. It is set by the new `releaseBranchPrefix` and `releaseHold` settings, and the title shows the hold. ([#973](https://github.com/cbundy/dev-system/pull/973))

## Changed

- **Factory loop spec describes the loop as built** - The v2 spec drops the first loop's history and build-only sections, keeping every cited section number; the build notes and foundation map are gone. ([#969](https://github.com/cbundy/dev-system/pull/969))

## Fixed

- **heartbeat-state shows the in-flight branch on the new event store** - Reading the new store, it now reports the branch of an issue in building, fixing or the merge queue, matching the old source. ([#968](https://github.com/cbundy/dev-system/pull/968))

## Upgrade

- Base image: restart workspaces (or rebuild the dev container) onto base image 2.47.1.
- Plugin: run `npx callum-dev update`, commit the `.claude/settings.json` it produces, then restart the container or run `dev-init --plugins`. A plain `/plugin marketplace update` does not advance the pinned ref.
- Factory loop: to use the release hold, set `releaseBranchPrefix` in `.claude/factory-loop.json` (dev-system uses `chore/release-`); it is off while unset.

## Verify

- On a release candidate, open a PR on a `chore/release-` branch and confirm the loop's title shows the merge queue held for it, and that the hold ends when it merges or after 10 minutes.
- Confirm the loop logs `hold:release` interventions at the start and end of the hold.
- Confirm a repo without `releaseBranchPrefix`, or with `releaseHold` 0, merges as before.
- On base image 2.47.1, run `heartbeat-state` against an issue in building and confirm the branch is filled with the new source.
